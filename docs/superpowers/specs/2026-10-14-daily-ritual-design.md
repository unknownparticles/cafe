# Daily Ritual 实现设计

## 目标与交付范围

实现 PRD 的全部 MVP（P0、P1）功能。用户已确认交付 60 张完整配方：经典咖啡、创意咖啡、烘焙甜品、冷藏甜品各 15 张。P2 不纳入此次范围。

## 方案比较

1. 推荐 React + TypeScript + Vite + 自有 Service Worker：符合 PRD，界面状态清晰，缓存行为可审查。
2. 原生 TypeScript + Vite：依赖较少，但多个页面与配方弹窗的状态管理维护成本较高。
3. React + PWA 插件：自动化缓存较方便，但额外引入框架配置，不利于初学者理解版本切换。

## 页面与视觉

使用奶油白背景、深咖啡棕文字、焦糖强调色、鼠尾草绿和淡粉卡面。系统衬线标题搭配系统无衬线正文，不依赖外部字体。原创 SVG 成品插画与线稿保持统一风格。

首页兼抽卡页：品牌导航、主题文案、咖啡/甜品/混合选择、大尺寸卡牌、抽取按钮。卡牌揭晓后可查看配方、收藏或再次抽取。

图鉴页：显示 60 张配方，支持名称/原料/风味搜索、分类、难度和收藏筛选。收藏页复用列表组件，并提供空状态。设置区包含动画开关、系统减少动态提示及安装说明。

详情使用可访问的对话框：配方插画、简介、时间、难度、份量、原料、步骤、器具、固定制作参数、过敏原、数据来源。关闭后恢复焦点；背景禁止滚动；键盘和触屏均可操作。

手机使用单卡和易触达按钮，平板/桌面扩展图鉴列数。覆盖竖屏、横屏、安全区域、长文字和字体放大，交互区域至少 44px。

## 数据与业务边界

配方位于 public/data/recipes.json；TypeScript 类型覆盖 PRD 全部字段，并增加四类分组。数量与单位分别保存。份量缩放只影响原料，蛋类提供称重提示，温度、时间、研磨度等参数保持基准值。

60 张配方采用本项目独立编写的文字和原创 SVG，不复制第三方图片。每条保存来源、授权说明、署名、审核状态及日期。数据审核检查结构、配比、步骤与过敏原；实际制作验证单独记录，不将自动检查冒充实测。

客户端抽卡遵循当前筛选；候选超过一张时排除上一次结果；只有一张时允许重复；空候选提示调整筛选。收藏和动画设置写入 localStorage，读写失败时继续使用内存并提示保存失败。

## 动画

三套模板：coffee-cup、coffee-pour、dessert-outline。按实际路径长度设置描边偏移，按路径顺序增加延迟。默认约 3.2 秒，分为按钮反馈、描边、翻转、信息揭晓四阶段。同步锁防止重复抽卡；支持跳过；页面隐藏时结束动画；异常和组件卸载均清理计时器。

尊重 prefers-reduced-motion 和用户动画开关，简化模式直接显示完整静态卡牌。揭晓结果通过 aria-live 提示。

## PWA 与缓存

提供 manifest、192/512 图标、Apple Touch Icon、离线后备页面。所有 URL 从统一 Vite base 派生，支持 Pages 子路径；导航采用 hash，刷新无需服务器重写。

构建时生成含内容版本的 Service Worker 资源清单。HTML 网络优先并回退到所属版本入口；JS/CSS 使用内容哈希；配方、SVG、图标按版本缓存优先；图片按需缓存并限制数量。新版本等待旧页面关闭再激活，保留旧客户端所需缓存，避免新旧数据混用。

显示首次缓存就绪、离线和网络恢复状态。Chromium 支持安装事件提示，iOS 提供“分享 → 添加到主屏幕”步骤。

## 校验与部署

构建前校验 60 张配方和各组数量、唯一 ID、必填字段、合法枚举、有效数量/单位、非空步骤、真实资源、来源完整性和 reviewed 状态。错误阻止构建和发布。

GitHub Actions 在 main 推送时执行锁文件安装、类型检查、数据校验、生产构建，然后上传 dist 并部署 github-pages 环境。部署任务依赖构建成功，使用 contents:read、pages:write、id-token:write 权限。实际仓库和远程地址由用户提供后核对。
